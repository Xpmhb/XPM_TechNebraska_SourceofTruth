## Operating protocol

1. Before creating content, strategy, scheduling, graphics or policy copy, read this ledger and the current Drive workbook alongside [brand voice](./brand_voice_and_tone.md), [brand strategy](./brand_strategy.md), [visual identity](./visual_identity.md) and [six-month strategy](./six_month_content_strategy_core_document.md).
2. After substantive client meetings, emails or ClickUp feedback, add one atomic record per decision/request. Preserve exact source URL, date, speaker, category, owner, status, next action, production implication, and last verified time. Use the next unique `TN-###` ID; do not recycle IDs.
3. Statuses: **Confirmed** = explicit client direction; **Approval required** = blocked until client review; **Revision needed** = adjust draft; **Open** = no resolution; **Working plan / Working recommendation** = discussed but not necessarily approved; **Partially confirmed** = verify remaining elements.
4. Distinguish historical scope from current agreement. Where a contract, calendar or ClickUp contradicts client feedback, record the conflict and request confirmation from Hunter before execution. Emily provides editorial approval for client posts; Hunter approves XPM/agent operational changes under [AGENTS.md](../AGENTS.md).
5. Changes to this repository, the Drive ledger or published material require explicit Hunter approval. No agent should treat a reminder or a meeting discussion as permission to publish.
6. After every approved change, update Drive, refresh this GitHub snapshot, and add source/approval links. Never overwrite original client wording or remove unresolved history.
